# Full-bleed фон под safe area — варианты решения

## Проблема

Глобальная safe area инсетит окно целиком, поэтому фоновый арт комнаты
(`DecorPlacementWindow`) обрезается по границе safe area (виден зазор за жёлтой
линией на notched-устройствах). Дизайн требует: **фон во весь экран, под чёлку и
home-indicator**, а в safe area остаётся только «хром».

**Правило (зафиксировано):** *critical interactive chrome остаётся в safe area;
decor/content может уходить под notch/home-indicator.* То есть кнопки/панели
инсетятся, а фон и декор на нём — нет. Автор контента должен понимать: слот,
заавторенный у самого края, на устройстве с чёлкой может частично уйти под неё —
это осознанный компромисс, критичный интерактив туда не ставим.

Хром = UI-обвязка вокруг контента: кнопка «назад», нижняя панель-скролл
инвентаря, бейджи `Used`/`I`, HUD. Контент = фон комнаты + декор.

## Как устроена safe area сейчас (факты из проекта)

- `SafeAreaLayout` висит на `SafeAreaRoot`; и `HudRoot`, и `WindowsRoot` — его дети
  ([UIManagerCanvas.prefab](../../Assets/Game/Core/UI/Prefabs/UIManagerCanvas.prefab), [SafeAreaLayout.cs](../../Assets/Game/Infrastructure/UIShared/SafeAreaLayout/SafeAreaLayout.cs)).
- `ResolveParent`: HUD → `HudRoot`, всё остальное → `WindowsRoot`
  ([UIManager.cs:195](../../Assets/Game/Core/UI/Core/UIManager.cs)). Оба под safe area.
- `FullScreenRoot` — полноэкранный сосед `SafeAreaRoot`, сейчас держит только
  Blocker и **не** прокинут в `UICanvasRoot`.
- В `DecorPlacementWindow` фон рисуется через `RoomImageRect` с
  **AspectRatioFitter (EnvelopeParent, aspect 0.484)**, который покрывает своего
  родителя. Родитель = корень окна = safe area → фон ограничен safe area.
  `ReferenceSizeOverlayScaler` масштабирует оверлей 783×1618 (со слот-анкорами) под
  `RoomImageRect`, поэтому расстановка декора привязана к арту.

## Варианты

### A — Инверсный safe-area-wrapper на кластере комнаты **(выбран)**

Дать `RoomImageRect` полноэкранного родителя через компонент
`SafeAreaInverseStretch` (зеркало `SafeAreaLayout`: растягивает rect на весь
физический экран, когда его родитель уже равен safe area). Хром остаётся сиблингами
под корнем окна — в safe area, **бесплатно**, без переinsет-а.

- **Плюсы:** локально (префаб окна + один переиспользуемый компонент); глобальный
  стек/UIManager не трогаем; хром корректен даром; над фоном нет маски, overflow
  рендерится.
- **Минусы:** компонент корректен только когда родитель = safe area (отражено в
  названии); дублирует safe-area-математику в инверсии.
- **Когда лучше всего:** ≤2 полноэкранных окна (внутри/снаружи фургона) — наш случай.

Реализация: компонент [SafeAreaInverseStretch.cs](../../Assets/Game/Infrastructure/UIShared/SafeAreaLayout/SafeAreaInverseStretch.cs)
+ узел `FullBleedRoot` в префабе на месте (sibling index) `RoomImageRect`, куда
`RoomImageRect` репарентится и центрируется.

### B — Разнести окно на слои: фон на `FullScreenRoot`, хром в safe area

Прокинуть `FullScreenRoot` в `UICanvasRoot`, положить room-кластер на полноэкранный
слой, хром — под safe area.

- **Плюсы:** архитектурно чистое разделение слоёв.
- **Минусы:** ломает модель «одно окно = одно поддерево»; контроллер владеет двумя
  поддеревьями или «порталом» для фона; самый тяжёлый путь.
- **Когда вернуться:** если фреймворк окон будет переходить на слоистые роты.

### C — Per-window opt-out из глобальной safe area + `SafeAreaLayout` на кластерах хрома

Признак «полноэкранное» окно (флаг в `[Window]` / роут в `ResolveParent` → парентить
в полноэкранный рут), внутри префаба навесить `SafeAreaLayout` на верхнюю и нижнюю
панели.

- **Плюсы:** стандартный мобильный паттерн (full-bleed арт, safe-area инсет на
  UI-кластерах); переиспользуемо для многих экранов.
- **Минусы:** правки в `UIManager.ResolveParent` + атрибут; каждое full-bleed окно
  обязано само инсетить свой хром — то, что вариант A получает даром.
- **Когда вернуться:** если full-bleed экранов станет много.

## Решение

**Вариант A** — при ≤2 однотипных окнах даёт максимум эффекта минимальными
средствами, и хром остаётся в safe area без ручного переinsет-а. Если позже
появится много полноэкранных экранов — мигрировать на **C** (переиспользуемый
паттерн); `FullScreenRoot` для этого уже существует, не хватает только роутинга.
